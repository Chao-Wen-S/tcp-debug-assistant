## 三、测试过程中发现并修复的缺陷

| # | 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | HEX 不支持 `0x` 前缀 | 输入 `0xAA 0xBB` 报“非法字符 x” | 解析器只认十六进制字符，`x` 被判非法 | 解析前用正则 `(?i)0x` 归一化为空格 |
| 2 | UTF-8 跨包中文乱码 | 中文被 TCP 拆包时显示 `�文` | 先用 `GetCharCount` 再用 `GetChars`，两次都推进解码器状态 | 改为单次 `GetChars` 并取返回长度 |
| 3 | 顶部配置面板不显示 | 启动后看不到“模式 / 服务器地址 / 端口 / 连接” | Dock 布局按 z 序反向处理，`Fill` 面板先占满整块，`Top` 面板被压成 0 高度 | `Controls.SetChildIndex(_mainSplit, 0)` 让 Fill 最后处理 |
| 4 | 客户端列表列被裁切 | 服务端模式“发送”列看不见，需横向滚动 | 4 列总宽 334px > 面板宽度 | 左栏默认宽度 380px，列宽 60/150/64/64 |
| 5 | 深色模式接收区仍是白底 | 深色主题下只有接收 / 发送区是纯白，刺眼 | RichTextBox 直接继承 TextBoxBase，case TextBox 匹配不到，从未被上色 | 判断类型改为 TextBoxBase |
| 6 | 深色模式系统标题栏发白 | 内容变深了，标题栏仍是系统浅色 | 未调用 DWM 深色接口 | DwmSetWindowAttribute（20 回退 19）+ SetWindowPos FRAMECHANGED |
| 7 | 右上角按钮缩放后消失 | 拉伸窗口后 GitHub / 主题按钮不见 | FlowLayoutPanel 反向 Dock 与缩放重排冲突 | 改手工定位 + Anchor Top\|Right |
| 8 | 列表表头与字节数被截断 | 显示“客…”“1.2 …”“6.4 …” | 列宽总和超出列表可用宽度（382px） | 列宽改为 74/140/84/84，左栏 424px |
| 9 | 行尾下拉文字被省略 | 显示 CRLF (r… | 自绘下拉可用文本区为 Width-32 | 宽度 112 改为 132 |
| 10 | 深色下数字框仍是白底 | 端口 / 间隔 / 定时周期在深色主题里保持系统白底黑字 | NumericUpDown 由系统主题绘制，BackColor / ForeColor 均被忽略（实测刷成纯红也不生效） | 改为自绘 NumberField：圆角字段 + 上下步进 + 无边框内嵌 TextBox |
| 11 | 服务端模式发送工具条被裁切 | 右栏 784px 时“清空”按钮被 sendHost 裁掉，“编码”下拉显示成“文…” | 工具条控件总宽 582px > 可用宽度 | 压缩下拉宽度与各处间距，总宽降到 550px 以内，编码框放宽到 84px |
| 12 | 客户端模式左边缘有灰条 | 折叠左栏后右栏贴边，留一条与主题不同色的空条 | Panel1Collapsed 后 Panel2 左边距仍为 0 | ApplyMode 里按模式设置 Panel2 的左边距 |

> 第 3 项是**截图核对**时发现的：`DrawToBitmap` 出来的图和真实控件树一致，直接暴露了“顶部面板消失”的布局问题。

> 第 5~9 项是 v1.1 用**真实屏幕截图**复核才发现的：`DrawToBitmap` 走 `WM_PRINT`，会按控件属性重绘，白底 / 标题栏 / 错位这类“真实重绘问题”只有抓屏才看得见。UI 回归建议一律“出图 + 抓屏”双份。

## 四、未覆盖 / 已知限制

- 未做 IPv6 地址解析与 SNI/TLS，仅裸 TCP。
- 未做数据持久化（会话记录不落盘，除“保存日志”外）。
- 接收区为文本视图，超长单行不自动换行（HEX 视图按块换行）。
- 压力测试上限为 1MB 单包与 5+ 并发客户端；未做万级连接压测。
